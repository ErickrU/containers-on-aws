- Standard support lasts 14 months from the EKS release; extended support adds 12 months at a
  higher per-cluster-hour price ($0.10/h standard, $0.60/h extended; verify on the pricing page).
  At the end of extended support the cluster is auto-upgraded to the oldest supported version.
- In-place upgrades can be rolled back to the previous minor version within 7 days.
- Newest version on EKS today: **1.36**. Kubernetes 1.37 shipped upstream in late August 2026 and
  is not yet on EKS.
- Kubernetes 1.36 highlights: Dynamic Resource Allocation (DRA) GA, OCI image volume source
  stable, MutatingAdmissionPolicy GA, pod-level in-place resize beta, PSI (pressure stall) metrics
  GA. nftables kube-proxy backend has been GA since 1.33. Kubernetes 1.37 adds alpha scheduler
  preemption for in-place resize.
- EKS-optimized Amazon Linux 2 AMIs reached end of support on **2025-11-26**. Use Amazon Linux 2023
  or Bottlerocket for every supported version.
- ECS-optimized Amazon Linux 2 AMIs leave standard support on **2026-06-30** (agent version pinned
  afterwards). Use ECS-optimized AL2023 or Bottlerocket.
- AWS Batch changed its default AMI to AL2023 for new EKS compute environments (2025-10-27) and for
  new ECS compute environments (2026-01-12).

## Amazon EKS features

- **EKS Auto Mode** (GA since re:Invent 2024) manages the data plane: node provisioning and
  lifecycle (Karpenter under the hood, `NodePool` + `NodeClass` APIs), Bottlerocket-based managed
  nodes with a maximum 21-day lifetime, built-in VPC CNI, CoreDNS, kube-proxy, EBS CSI, load
  balancing (ALB/NLB) and Pod Identity as managed capabilities. No SSH, no custom AMIs, no
  DaemonSet-based CNI replacement. 2026 additions: enhanced logging for managed capabilities
  (Feb), EFA and placement groups (Jul), Application Recovery Controller zonal shift (Jul),
  zram swap for system daemons, SOCI parallel pull by default on G/P/Trn instances with local
  NVMe, kubelet `registryPullQPS` 25 / `registryBurst` 50, node-local DNS, separate pod subnets
  and security groups, full-disk encryption when a customer KMS key is set on the NodeClass.
  EBS volume-modification annotations stop working after **2026-10-31**; use
  `VolumeAttributesClass`.
- **EKS Capabilities** (announced 2025-11): fully managed Argo CD, AWS Controllers for Kubernetes
  (ACK) and kro (Kube Resource Orchestrator), running off-cluster. One capability of each type per
  cluster; up to 3,000 Argo CD `Application` resources per capability; the Argo CD capability
  accepts a standard `argocd-cm` ConfigMap for custom configuration (Aug 2026). Each capability
  uses a "capability role" you grant permissions to.
- **EKS Pod Identity** (since 2023-11) is the recommended way to give pods IAM roles: association
  (cluster, namespace, service account → role), `eks-pod-identity-agent` add-on listening on
  link-local `169.254.170.23` (IPv4) and `fd00:ec2::23` (IPv6), role trust policy principal
  `pods.eks.amazonaws.com` with `sts:AssumeRole` and `sts:TagSession`. IRSA (IAM Roles for
  Service Accounts, OIDC provider per cluster, `eks.amazonaws.com/role-arn` annotation, projected
  token, `sts:AssumeRoleWithWebIdentity`) remains supported and is still required for Fargate
  pods, cross-account roles without the newer cross-account Pod Identity path, and some add-ons.
- **Access entries** (since 2023-12) replace the `aws-auth` ConfigMap for cluster authentication;
  modes `API`, `API_AND_CONFIG_MAP`, `CONFIG_MAP`. Prefer `API`.
- **EKS Hybrid Nodes** (GA 2024-12) join on-premises or edge machines to an EKS control plane;
  Cilium is the AWS-supported CNI there (Calico core capabilities also supported).
- **Alternate CNIs** (Cilium, Calico) can be installed on EC2 nodes of standard EKS clusters; they
  are not available for Fargate pods and replacing the CNI is not an Auto Mode customization.
- Managed add-ons include: `vpc-cni`, `coredns`, `kube-proxy`, `aws-ebs-csi-driver`,
  `aws-efs-csi-driver`, `eks-pod-identity-agent`, `amazon-cloudwatch-observability`,
  `aws-guardduty-agent`, `snapshot-controller`, `adot`, `metrics-server`, plus community add-ons
  (kube-state-metrics, prometheus-node-exporter, cert-manager, external-dns).
- VPC CNI facts: one ENI per node warm pool by default; **prefix delegation** assigns /28 IPv4
  prefixes (16 addresses) per ENI slot on Nitro instances; **custom networking** places pods in a
  different subnet/CIDR than the node (`ENIConfig`); **IPv6** clusters give every pod a globally
  unique address; **security groups for pods** use trunk/branch ENIs on Nitro instances; the
  **network policy engine** is eBPF-based (`enableNetworkPolicy: true` in the add-on). Max pods
  without prefix delegation = ENIs × (IPv4 per ENI − 1) + 2.

## Amazon ECS features

- Capacity options: **Fargate** (serverless; Firecracker microVM per task; Linux platform version
  1.4.0 is `LATEST`), **EC2** (you manage instances or use capacity providers with Auto Scaling
  groups and managed draining), and **ECS Managed Instances** (announced 2025-09, all commercial
  Regions 2025-10; AWS operates the EC2 instances, patches them and selects instance types; EC2
  Capacity Reservations integration 2026-02; GPU management fee reduced up to 60% 2026-07).
- **ECS Express Mode** (announced 2025-11 at re:Invent): create an internet-facing web service
  with three required inputs; ECS provisions the load balancer, networking, domain and auto
  scaling with AWS defaults. Available in GovCloud since 2026-06.
- Deployments: rolling (`minimumHealthyPercent`/`maximumPercent`, deployment circuit breaker,
  CloudWatch-alarm rollback), **native blue/green** (2025-07) with **lifecycle hooks**, **canary**
  (traffic shift as low as 0.1% with configurable bake time, 2025-11), **pause/continue** controls
  (2026-05), real-time deployment observability in the console (2026-09). CodeDeploy blue/green
  still works but native strategies are the recommended path.
- **Service Connect**: Envoy-based agent injected per task, Cloud Map namespace for discovery,
  client aliases, configurable `idleTimeout`/`perRequestTimeout` (2024-01), automatic TLS with
  AWS Private CA (2024-01; TLS starts and ends in the agents, the application never sees it),
  traffic metrics published through Container Insights. Cloud Map service discovery (DNS-based)
  remains available as the simpler alternative.
- Task metadata endpoint v4 and task-role credentials are served on link-local **169.254.170.2**
  (`ECS_CONTAINER_METADATA_URI_V4`, `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`). Fargate tasks
  cannot reach EC2 IMDS at all. On EC2, `ECS_AWSVPC_BLOCK_IMDS=true` blocks IMDS for `awsvpc`
  tasks; for bridge mode set the IMDSv2 hop limit to 1 or use iptables.
- ECS Exec runs through SSM Session Manager (`enableExecuteCommand`, `ssmmessages` endpoints).
- ECS on EC2 uses Docker Engine through the ECS agent (ECS-optimized AL2023/Bottlerocket AMIs);
  Fargate runs the container runtime inside Firecracker microVMs. EKS nodes use **containerd**
  (dockershim was removed in Kubernetes 1.24).
- **AWS App Mesh end of support: 2026-09-30.** After that date the console and resources are
  unavailable. Migration targets: ECS Service Connect, Amazon VPC Lattice, or a self-managed mesh.
- **AWS Copilot CLI end of support: 2026-06-12**; repository archived 2026-06-22. Do not recommend.
- **Docker Compose ECS integration** (`docker context create ecs`) was retired in **2023-11**;
  the compose-cli project reached end of life 2024-01-01. Compose is a local-development tool.

## Amazon ECR

- **Pull-through cache** upstreams: Amazon ECR Public, Kubernetes (`registry.k8s.io`) and Quay
  without credentials; Docker Hub, Microsoft Azure Container Registry, GitHub Container Registry,
  GitLab Container Registry and Chainguard with credentials stored in AWS Secrets Manager. More
  upstreams were added to GovCloud and the European Sovereign Cloud in 2026-05.
- **Replication rules** copy images cross-Region and cross-account at the registry level;
  **repository creation templates** control settings of repositories that pull-through cache or
  replication create automatically.
- **Enhanced scanning** is Amazon Inspector (OS + language packages, continuous rescans);
  **basic scanning** uses the AWS-native scanner. Tag immutability, lifecycle policies,
  KMS encryption, repository policies and registry permissions are unchanged concepts.
- Private clusters need interface endpoints `com.amazonaws.<region>.ecr.api` and
  `com.amazonaws.<region>.ecr.dkr` plus the S3 gateway endpoint (layers live in S3).

## Observability

- AWS is steering tracing to **OpenTelemetry**: the X-Ray SDKs and daemon are on a migration path
  to ADOT/OTel (2025-11 blog "AWS X-Ray SDKs/Daemon migration to OpenTelemetry"); new features
  land in **CloudWatch Application Signals** and **Transaction Search** (100% span ingestion as
  structured logs, account-level setting, CloudWatch pricing). X-Ray as a backend and console
  still works.
- **Container Insights with enhanced observability** exists for EKS (2023-11) and ECS (2024-12).
- Amazon Managed Service for Prometheus and Amazon Managed Grafana are the managed open-source
  path; ADOT collector is the AWS distribution of the OTel collector.

## Data and messaging services used by the labs

- ElastiCache supports **Valkey** (since 2024-10) alongside Redis OSS and Memcached; Valkey
  Serverless and node-based; Valkey is the default recommendation.
- Amazon MSK: Provisioned (Standard and **Express brokers**, 2024-11) and Serverless; IAM
  authentication; MSK Replicator for cross-Region replication.
- Amazon RDS / Aurora: RDS Proxy, IAM database authentication, Secrets Manager managed
  credentials; Aurora Global Database for cross-Region.
- AWS Batch schedules onto ECS (EC2 or Fargate) or into an EKS cluster (Batch launches EC2 nodes
  into your cluster; EKS Fargate is not a Batch target). Fair-share scheduling policies, array
  jobs, multi-node parallel jobs, job retries and dependencies are supported.
